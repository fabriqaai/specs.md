# Planning skills

The shaping side of the flow, all optional-order: `intent-capture` (dialogue → brief.md), `work-item-decompose` (vertical slices, complexity assessment, acceptance criteria, dependency validation), and `bolt-plan` — the optional **draft bolts** skill: writes bolt *proposals* (grouping + recipe hints) that `bolt-start` may adopt, regroup, or ignore.

## Acceptance criteria

- All three are verb skills (`disable-model-invocation: true`), invocable at any time — no phase precondition.
- `work-item-decompose` applies the autonomy-bias matrix (complexity × bias → suggested ceremony) as a *recommendation* recorded in frontmatter.
- `bolt-plan` output is data (draft bolt files or a proposals section), not commands — planned-ahead and dynamic grouping are the same structure at different times.
- No "REQUIRED NEXT SKILL" chains anywhere; each skill ends by stating what state now exists.
